# C#：优先写重载，而不是默认参数

## 核心原则

C# 对外暴露的 API 优先写成重载，不要用带默认值的可选参数表达同一件事。

重载把每种调用形态都变成一个明确的命名入口；默认参数则把差异藏在调用处，读者必须回看签名才知道哪些参数被省略、省掉的到底是什么语义。

## 为什么

- **签名即文档**：`GetAllPositions()` 与 `GetAllPositions(ICollection<Vector2I>)` 是两条清晰的路；`GetAllPositions(collection, reachableOnly: true)` 里的 `true` 在调用点没有名字，容易误读。
- **避免“形同虚设”的参数**：默认参数叠加分支时，很容易出现某个参数根本没人读、却因有默认值而长期不被发现（等于给调用方一个假承诺）。
- **改动更安全**：重载可以各自演进；默认参数一旦改了默认值或顺序，所有省略该参数的调用点语义会悄悄变化。

## 例外：热路径为降低调用栈

只有明确的热频代码，且已确认调用开销重要时，才用默认参数合并重载，以减少一层转发调用栈。此时应在条目或提交说明里写清理由，不要为“少敲几个字”而用默认参数。

## 判断标准

- 默认写法：拆成多个重载，每个重载只做本形态的事。
- 例外写法：先量到性能问题，再合并；没有测量依据就不要预优化。
